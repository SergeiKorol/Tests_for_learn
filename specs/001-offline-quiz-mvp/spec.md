# Feature Specification: Offline Quiz App — MVP

**Feature Branch**: `001-offline-quiz-mvp`

**Created**: 2026-07-31

**Status**: Draft

**Input**: User description: «Офлайн PWA-приложение для текстовых тестов с встроенным
ознакомительным тестом, загрузкой тестов из GitHub, импортом JSON, прохождением
тестов, историей и настройками. Полностью локальное хранение данных.»

## Clarifications

### Session 2026-07-31

- Q: Как засчитываются вопросы, на которые пользователь не ответил к моменту завершения теста (вручную или по таймеру)? → A: Считаются неверными; в знаменателе все вопросы теста.
- Q: Когда именно восстанавливается встроенный тест «Знакомство с приложением», если он был удалён при очистке данных? → A: Только при явном действии «Сбросить настройки до стандартных» или «Удалить все скачанные тесты и историю»; не при обычном перезапуске приложения.
- Q: Что происходит с историей попыток, когда пользователь скачивает обновлённую версию уже загруженного теста? → A: История по этому testId удаляется при скачивании новой версии; перед удалением показывается предупреждение.
- Q: Как пользователь завершает тест без ограничения по времени (`timeLimit: 0`)? → A: Кнопка «Завершить» доступна на любом вопросе; при наличии неотвеченных вопросов — обязательное подтверждение перед завершением.
- Q: Что происходит с историей попыток при импорте JSON с существующим id и выборе «Перезаписать»? → A: Как при обновлении версии: предупреждение об удалении истории → при подтверждении история по testId удаляется → перезапись теста.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Первый запуск и ознакомительный тест (Priority: P1)

Новый пользователь открывает приложение впервые (в том числе без интернета) и
сразу видит один доступный тест «Знакомство с приложением». Он проходит его,
знакомится с интерфейсом (вопросы, варианты ответов, навигация, экран
результата) и узнаёт о переключении тёмной темы через вопрос «Можно ли включить
тёмную тему с помощью кнопки «Тема»?» (правильный ответ — «Да»).

**Why this priority**: Без встроенного теста приложение пустое при первом запуске;
это единственный способ показать ценность продукта офлайн и без регистрации.

**Independent Test**: Установить приложение, отключить сеть, открыть — в списке
ровно один тест; пройти его до экрана результата без ошибок.

**Acceptance Scenarios**:

1. **Given** приложение открыто впервые и локальное хранилище пусто,
   **When** загрузка завершена,
   **Then** в списке отображается ровно один тест «Знакомство с приложением»
   с пометкой, что он встроенный.
2. **Given** пользователь на главном экране без интернета,
   **When** он открывает ознакомительный тест,
   **Then** тест полностью доступен: вопросы, варианты, навигация и результат
   работают без сетевых запросов.
3. **Given** пользователь проходит ознакомительный тест,
   **When** он отвечает на все вопросы,
   **Then** отображается экран результата со счётом, процентом и разбором
   правильных/неправильных ответов.

---

### User Story 2 — Прохождение теста и сохранение результата (Priority: P1)

Пользователь выбирает любой доступный тест из списка, отвечает на вопросы с
навигацией вперёд/назад (включая пропуск и возврат), при необходимости видит
таймер, завершает тест и получает детальный результат, который сохраняется
локально.

**Why this priority**: Прохождение тестов — основная функция продукта; результат
должен сохраняться для истории.

**Independent Test**: Имея хотя бы один тест в списке, пройти его, увидеть
результат, перезапустить приложение — попытка должна остаться в истории.

**Acceptance Scenarios**:

1. **Given** пользователь открыл тест с N вопросами,
   **When** он на экране вопроса,
   **Then** отображаются прогресс «вопрос X из Y» и варианты ответа.
2. **Given** у теста задан лимит времени больше нуля,
   **When** пользователь начинает прохождение,
   **Then** отображается обратный отсчёт; по истечении времени тест
   автоматически завершается с текущими ответами.
3. **Given** пользователь ответил на часть вопросов,
   **When** он нажимает «Назад» или «Вперёд»,
   **Then** может свободно переключаться между вопросами; ранее выбранные
   ответы сохраняются в рамках сессии прохождения.
4. **Given** тест с `timeLimit: 0`,
   **When** пользователь на любом вопросе нажимает «Завершить тест»,
   **Then** при наличии неотвеченных вопросов показывается подтверждение со
   списком или числом пропущенных; при согласии тест завершается.
5. **Given** пользователь завершил тест (в том числе с неотвеченными вопросами),
   **When** отображается экран результата,
   **Then** неотвеченные вопросы засчитаны как неверные; показаны счёт (X/Y, где Y
   — все вопросы теста), процент и подсветка правильных/неправильных/пропущенных
   ответов; попытка сохранена локально.

### User Story 3 — Загрузка тестов из удалённого источника (Priority: P2)

Пользователь с интернетом нажимает «Проверить новые тесты», получает каталог
тестов из настроенного источника, видит статус каждого («доступен для
скачивания» / «уже загружен»), выборочно или массово скачивает новые тесты с
индикатором прогресса; после загрузки тесты сразу доступны офлайн.

**Why this priority**: Расширяет библиотеку тестов beyond встроенного; ключевая
функция для регулярного использования.

**Independent Test**: При наличии сети проверить каталог, скачать один тест,
отключить сеть — скачанный тест проходится без ошибок.

**Acceptance Scenarios**:

1. **Given** есть интернет и настроен URL источника,
   **When** пользователь нажимает «Проверить новые тесты»,
   **Then** приложение загружает каталог и показывает список с чекбоксами и
   статусами для каждого теста.
2. **Given** в каталоге тест с id, которого нет локально, или с версией выше
   локальной,
   **When** список отображён,
   **Then** тест помечен как «доступен для скачивания».
3. **Given** локальная версия теста совпадает с версией в каталоге,
   **When** список отображён,
   **Then** тест помечен как «уже загружен».
4. **Given** пользователь выбрал один или несколько тестов,
   **When** нажимает «Скачать выбранное» или «Скачать все новые»,
   **Then** отображается индикатор прогресса; по завершении тесты появляются
   в главном списке и доступны офлайн.
5. **Given** локально загружен тест, а в каталоге доступна более новая version,
   **When** пользователь инициирует скачивание обновления,
   **Then** показывается предупреждение об удалении истории попыток по этому
   testId; при подтверждении история удаляется, затем загружается новая версия.
6. **Given** нет интернета,
   **When** пользователь нажимает «Проверить новые тесты»,
   **Then** показывается сообщение «Нет подключения к интернету»; локальные
   тесты остаются доступны.

### User Story 4 — Смена источника тестов (Priority: P2)

Пользователь в настройках меняет URL репозитория (например, на свой форк или
другой статический хостинг с аналогичной структурой). Следующая проверка новых
тестов использует новый источник. Авторизация не требуется — только публичные
файлы по HTTPS.

**Why this priority**: Гибкость источника — заявленное конкурентное
преимущество; нужна до активного использования сторонних каталогов.

**Independent Test**: Изменить URL в настройках, проверить новые тесты —
каталог загружается с нового адреса.

**Acceptance Scenarios**:

1. **Given** пользователь в разделе настроек,
   **When** он видит поле «Источник тестов»,
   **Then** отображается текущий URL (по умолчанию — URL основного репозитория
   проекта).
2. **Given** пользователь вводит URL, начинающийся с `https://`,
   **When** сохраняет настройку,
   **Then** URL сохраняется локально; при следующей проверке каталог
   запрашивается относительно этого базового пути (`/index.json` и файлы тестов).
3. **Given** пользователь вводит некорректный URL (не HTTPS или пустой),
   **When** пытается сохранить,
   **Then** отображается понятная ошибка; прежнее значение не перезаписывается.

### User Story 5 — Импорт теста из файла (Priority: P3)

Пользователь получает JSON-файл теста (например, от преподавателя) и через
«Импортировать тест из JSON» в настройках выбирает файл на устройстве. При
успешной проверке формата тест добавляется в список; при конфликте id —
предлагается перезаписать или отменить.

**Why this priority**: Альтернативный канал получения контента без GitHub;
важно для образовательных сценариев, но не блокирует базовый MVP.

**Independent Test**: Импортировать валидный JSON — тест появляется в списке и
проходится; импорт файла с существующим id — диалог перезаписи.

**Acceptance Scenarios**:

1. **Given** пользователь в настройках,
   **When** выбирает «Импортировать тест из JSON» и указывает `.json` файл,
   **Then** открывается системный диалог выбора файла (только JSON).
2. **Given** файл содержит валидный тест (id, title, questions с корректными
   correctIndex),
   **When** импорт завершён,
   **Then** тест немедленно появляется в главном списке.
3. **Given** тест с таким id уже существует локально,
   **When** пользователь импортирует файл и выбирает «Перезаписать»,
   **Then** показывается предупреждение об удалении истории попыток по этому
   testId; при подтверждении история удаляется, тест перезаписывается; при
   отмене данные не изменяются.
4. **Given** тест с таким id уже существует локально,
   **When** пользователь выбирает «Отменить» в диалоге конфликта,
   **Then** импорт прерывается; тест и история остаются без изменений.
5. **Given** файл повреждён или не соответствует формату,
   **When** импорт выполняется,
   **Then** показывается понятное сообщение об ошибке; данные не изменяются.

### User Story 6 — История и статистика (Priority: P3)

Пользователь открывает раздел «История», видит все попытки по всем тестам
(название, дата/время, X/Y, процент), может открыть детали попытки (какие ответы
даны и верны ли они), видит сводку по тесту (число попыток, средний балл,
лучшая/худшая попытка) и при необходимости очищает историю с подтверждением.

**Why this priority**: Мотивация и отслеживание прогресса; зависит от Story 2.

**Independent Test**: Пройти тест дважды — в истории две записи со статистикой;
очистить историю — список пуст, тесты остаются.

**Acceptance Scenarios**:

1. **Given** пользователь завершил хотя бы одну попытку,
   **When** открывает «История»,
   **Then** видит список попыток, отсортированный по дате (новые сверху).
2. **Given** пользователь выбрал попытку,
   **When** открывает детали,
   **Then** видит каждый вопрос, выбранный и правильный ответ, статус
   (верно/неверно).
3. **Given** по одному тесту несколько попыток,
   **When** пользователь смотрит сводку по тесту,
   **Then** отображаются: количество попыток, средний процент, лучший и
   худший результат.
4. **Given** пользователь нажимает «Очистить историю»,
   **When** подтверждает действие,
   **Then** все записи попыток удалены; тесты и настройки сохранены.

---

### User Story 7 — Настройки приложения (Priority: P3)

Пользователь переключает тёмную/светлую тему, выбирает язык интерфейса
(русский / английский, по умолчанию русский), управляет данными: удаляет все
скачанные тесты и историю (с подтверждением), сбрасывает настройки к
стандартным. При полном сбросе данных встроенный тест восстанавливается.

**Why this priority**: Персонализация и контроль данных; не блокирует первый
опыт.

**Independent Test**: Сменить тему и язык — после перезапуска настройки
сохранены; полный сброс — один встроенный тест, настройки по умолчанию.

**Acceptance Scenarios**:

1. **Given** пользователь переключает тему,
   **When** возвращается в приложение позже,
   **Then** выбранная тема сохранена.
2. **Given** пользователь выбирает язык «English»,
   **When** интерфейс обновлён,
   **Then** все элементы UI отображаются на английском до смены языка.
3. **Given** пользователь выбирает «Удалить все скачанные тесты и историю»,
   **When** подтверждает,
   **Then** удалены все скачанные и импортированные тесты и вся история;
   встроенный тест восстанавливается в рамках этого же подтверждённого действия.
4. **Given** пользователь нажимает «Сбросить настройки до стандартных»,
   **When** подтверждает,
   **Then** URL источника, тема и язык возвращаются к значениям по умолчанию;
   встроенный тест восстанавливается, если отсутствовал.
5. **Given** встроенный тест отсутствует в хранилище после предыдущих действий
   пользователя,
   **When** пользователь просто перезапускает приложение без сброса,
   **Then** встроенный тест НЕ восстанавливается автоматически.

### User Story 8 — Установка PWA и офлайн-оболочка (Priority: P2)

Пользователь устанавливает приложение на устройство (телефон или ПК) как
нативное через предложение браузера. В standalone-режиме нет браузерной
оболочки. Оболочка приложения и уже загруженный контент работают офлайн; при
отсутствии сети интерфейс не показывает лишних ошибок, кроме явных сетевых
действий.

**Why this priority**: PWA — способ доставки продукта на все платформы; критично
для мобильного UX.

**Independent Test**: Установить PWA, закрыть браузер, открыть с иконки —
приложение работает; офлайн доступны встроенный и скачанные тесты.

**Acceptance Scenarios**:

1. **Given** браузер поддерживает установку PWA,
   **When** пользователь соглашается установить приложение,
   **Then** появляется иконка на домашнем экране / в меню приложений.
2. **Given** приложение запущено в standalone-режиме,
   **When** пользователь работает с локальными тестами,
   **Then** не отображается адресная строка и элементы браузера.
3. **Given** оболочка была загружена хотя бы раз,
   **When** пользователь офлайн открывает приложение,
   **Then** главный экран и локальные тесты доступны без ошибок загрузки.

### Edge Cases

- Первый запуск без интернета: только встроенный тест; «Проверить новые тесты»
  неактивна или показывает «Нет сети».
- Каталог `index.json` недоступен (404, таймаут): понятное сообщение; локальные
  данные не затронуты.
- Скачанный тест повреждён или не проходит валидацию: ошибка для этого теста,
  остальные загрузки продолжаются.
- Прерывание скачивания (потеря сети): частично загруженные тесты не добавляются
  в список; пользователь может повторить попытку.
- Тест с `timeLimit: 0`: таймер не отображается; завершение через «Завершить
  тест» на любом вопросе с подтверждением при пропусках.
- Неотвеченные вопросы при завершении (вручную или по таймеру): засчитываются
  как неверные; в истории сохраняются с `chosenIndex: null` или без записи для
  пропущенного вопроса, но вопрос отображается как «не отвечен / неверно».
- Единственный вопрос в тесте: навигация и прогресс корректны (1 из 1).
- Импорт теста с id `__builtin_welcome__`: трактуется как перезапись встроенного
  с предупреждением.
- Очень длинные названия тестов и вопросов: UI не ломается на экранах от 320px.
- Пустой каталог в `index.json`: сообщение «Новых тестов не найдено».
- Дублирование id в каталоге: используется первая запись; остальные игнорируются
  с предупреждением в логе (не блокирует пользователя).
- Встроенный тест удалён и пользователь перезапустил приложение без сброса:
  список тестов без встроенного; восстановление только через FR-031 или FR-032.
- Обновление версии скачанного теста: перед загрузкой — предупреждение;
  при отказе история и локальная версия сохраняются; при согласии история
  по testId удаляется.
- Импорт с перезаписью существующего id: та же политика удаления истории,
  что и при обновлении версии (FR-009a, FR-019).

## Requirements *(mandatory)*

### Functional Requirements

**Первый запуск и встроенный тест**

- **FR-001**: При первом открытии (локальное хранилище пусто) приложение MUST
  автоматически добавить один встроенный тест «Знакомство с приложением»
  (id: `__builtin_welcome__`). При последующих запусках без явного сброса
  автоматическое восстановление MUST NOT выполняться.
- **FR-002**: Встроенный тест MUST быть помечен как встроенный и доступен без
  интернета с первого запуска.
- **FR-003**: Ознакомительный тест MUST содержать вопрос о включении тёмной темы
  через кнопку «Тема» с правильным ответом «Да».

**Главный экран и список тестов**

- **FR-004**: Главный экран MUST отображать список всех локально доступных
  тестов с названием и признаком встроенный/скачанный/импортированный.
- **FR-005**: Главный экран MUST содержать выделенную кнопку «Проверить новые
  тесты» и счётчик доступных локальных тестов.

**Загрузка из удалённого источника**

- **FR-006**: По запросу пользователя приложение MUST загружать каталог
  `index.json` относительно настроенного базового URL источника.
- **FR-007**: Каталог MUST содержать для каждого теста: id, title, description
  (опционально), version, questionsCount, filename (опционально).
- **FR-008**: Если filename отсутствует, путь к файлу теста MUST формироваться
  как `tests/{id}.json` относительно базового URL.
- **FR-009**: Приложение MUST сравнивать каталог с локальными тестами по id и
  version и показывать статус «доступен для скачивания» или «уже загружен».
- **FR-009a**: При скачивании версии теста, превышающей локальную, MUST
  показываться предупреждение об удалении истории попыток по этому testId;
  при подтверждении все попытки по testId MUST быть удалены до записи новой
  версии теста. При отмене скачивание MUST NOT выполняться.
- **FR-010**: Пользователь MUST иметь возможность выбрать отдельные тесты
  (чекбоксы) или скачать все новые одной командой.
- **FR-011**: Во время скачивания MUST отображаться индикатор прогресса.
- **FR-012**: При отсутствии сети при проверке новых тестов MUST показываться
  сообщение «Нет подключения к интернету».

**Источник тестов**

- **FR-013**: В настройках MUST быть поле «Источник тестов» с URL по умолчанию
  основного репозитория проекта.
- **FR-014**: URL MUST сохраняться локально и применяться при следующей проверке
  каталога.
- **FR-015**: URL MUST принимать только значения, начинающиеся с `https://`.
- **FR-016**: Авторизация на GitHub MUST NOT требоваться.

**Импорт из файла**

- **FR-017**: MUST быть опция «Импортировать тест из JSON» в настройках.
- **FR-018**: Импорт MUST принимать только файлы JSON и проверять наличие полей
  id, title, questions и корректность correctIndex в каждом вопросе.
- **FR-019**: При конфликте id MUST предлагаться перезапись или отмена. При
  выборе «Перезаписать» MUST показываться предупреждение об удалении истории
  попыток по testId (аналогично FR-009a); при подтверждении история MUST быть
  удалена до записи импортированного теста.

**Прохождение теста**

- **FR-020**: При прохождении MUST отображаться прогресс «вопрос X из Y».
- **FR-021**: Если timeLimit > 0, MUST отображаться таймер и автозавершение по
  истечении времени (без дополнительного подтверждения). Если timeLimit = 0,
  MUST быть кнопка «Завершить тест», доступная на любом вопросе.
- **FR-022**: MUST быть навигация «Назад»/«Вперёд» с сохранением выбранных
  ответов в рамках попытки. При нажатии «Завершить тест» с неотвеченными
  вопросами MUST показываться обязательное подтверждение; при отказе
  пользователь остаётся в тесте.
- **FR-023**: По завершении MUST показываться счёт, процент и разбор ответов.
  Неотвеченные вопросы MUST засчитываться как неверные; `totalQuestions` и
  знаменатель процента MUST равняться общему числу вопросов теста.
- **FR-024**: Каждая завершённая попытка MUST сохраняться локально с привязкой
  к testId, датой, score, totalQuestions и снимком ответов.

**История и статистика**

- **FR-025**: Раздел «История» MUST показывать все попытки: название теста,
  дата/время, X/Y, процент.
- **FR-026**: MUST быть детальный просмотр попытки с указанием выбранных и
  правильных ответов.
- **FR-027**: MUST быть сводная статистика по тесту: число попыток, средний
  балл, лучшая и худшая попытка.
- **FR-028**: MUST быть очистка истории с подтверждением.

**Настройки**

- **FR-029**: MUST быть переключатель тёмной/светлой темы с локальным
  сохранением.
- **FR-030**: MUST быть выбор языка интерфейса: русский (по умолчанию) и
  английский.
- **FR-031**: MUST быть «Удалить все скачанные тесты и историю» с
  подтверждением; по завершении MUST восстанавливаться встроенный тест.
- **FR-032**: MUST быть «Сбросить настройки до стандартных» с подтверждением;
  по завершении MUST восстанавливаться встроенный тест, если он отсутствовал.
- **FR-033**: Встроенный тест MUST восстанавливаться только при явных действиях
  FR-031 или FR-032, а не при обычном перезапуске приложения.

**PWA и офлайн**

- **FR-034**: Приложение MUST поддерживать установку как PWA на поддерживаемых
  платформах.
- **FR-035**: В standalone-режиме MUST отсутствовать браузерная оболочка.
- **FR-036**: Встроенный и скачанные тесты MUST работать офлайн всегда после
  загрузки/инициализации.
- **FR-037**: Приложение MUST NOT отправлять пользовательские данные на
  внешние серверы.

**Дизайн и UX**

- **FR-038**: Интерфейс MUST быть минималистичным и адаптивным (одна колонка на
  телефоне, контент до 800px на десктопе).
- **FR-039**: Каталог удалённых тестов MUST отображаться в модальном окне или
  раскрывающейся панели с чекбоксами и кнопкой «Скачать выбранное».
- **FR-040**: Корректное отображение MUST обеспечиваться на экранах от 320px до
  4K.

### Key Entities

- **Test (Тест)**: Локально сохранённый набор вопросов. Атрибуты: id (уникальный
  slug), title, description (опционально), version, timeLimit (секунды, 0 = без
  лимита), questions[], признак builtin, дата загрузки. Каждый question: id,
  text, options[], correctIndex.

- **CatalogEntry (Запись каталога)**: Элемент удалённого `index.json`: id, title,
  description, version, questionsCount, filename (опционально). Используется для
  сравнения с локальными тестами, не хранится постоянно как отдельная сущность.

- **QuizAttempt (Попытка)**: Одно прохождение теста. Атрибуты: testId, дата/время,
  score, totalQuestions (всегда равно числу вопросов теста), answersSnapshot[]
  ({ questionId, chosenIndex | null }). `chosenIndex: null` — вопрос не отвечен,
  засчитывается как неверный.

- **AppSettings (Настройки)**: Пара ключ-значение: URL источника, тема, язык
  интерфейса. Сохраняются локально между сессиями.

- **RemoteCatalog (Удалённый каталог)**: Массив CatalogEntry, загружаемый по
  запросу пользователя; не является постоянным хранилищем приложения.

### Формат данных (контракт)

**Файл теста (JSON)**:

```json
{
  "id": "unique-slug",
  "title": "Название теста",
  "description": "Описание (опционально)",
  "version": 1,
  "timeLimit": 0,
  "questions": [
    {
      "id": "q1",
      "text": "Текст вопроса",
      "options": ["Вариант A", "Вариант B"],
      "correctIndex": 0
    }
  ]
}
```

**Каталог index.json**:

```json
[
  {
    "id": "math-101",
    "title": "Математика, 5 класс",
    "description": "Базовый тест",
    "version": 2,
    "questionsCount": 10,
    "filename": "tests/math-101.json"
  }
]
```

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Новый пользователь без интернета может открыть приложение и
  завершить ознакомительный тест за 5 минут или меньше.
- **SC-002**: 100% функций прохождения теста, истории и настроек доступны
  офлайн после первоначальной инициализации (без сетевых запросов).
- **SC-003**: Пользователь с интернетом может обнаружить и скачать новый тест из
  каталога и начать его прохождение в течение 2 минут после нажатия «Проверить
  новые тесты» (при типичном размере теста до 50 вопросов).
- **SC-004**: Импорт валидного JSON-файла добавляет тест в список за одну
  операцию (не более 3 действий пользователя: открыть настройки → импорт →
  выбрать файл).
- **SC-005**: Интерфейс корректно отображается на viewport 320px, 768px и 1920px
  без горизонтальной прокрутки и обрезания ключевых элементов.
- **SC-006**: Ни одно пользовательское действие (ответы, история, настройки) не
  передаётся на внешний сервер — проверяемо отсутствием исходящих запросов с
  телом пользовательских данных.
- **SC-007**: После установки PWA приложение запускается с домашнего экрана и
  показывает главный список тестов без адресной строки браузера.
- **SC-008**: 90% пользователей успешно переключают тему и находят её через
  ознакомительный тест с первой попытки (usability-критерий для демо-теста).

## Assumptions

- Целевая аудитория: учащиеся и самостоятельно обучающиеся; авторизация не
  требуется.
- URL источника по умолчанию указывает на публичный репозиторий проекта с
  структурой `index.json` + `tests/*.json`; точное значение задаётся при
  развёртывании.
- Все тесты в удалённом источнике — публичные статические файлы по HTTPS.
- Пользователь сам инициирует проверку обновлений; фоновая синхронизация вне
  scope MVP.
- Поддерживаются только текстовые вопросы с вариантами ответа (single choice).
- Локализация интерфейса ограничена русским и английским языками в MVP.
- Современные браузеры с поддержкой PWA (Chrome, Edge, Safari, Firefox — актуальные
  версии на мобильных и десктопе).

## Out of Scope (MVP)

- Создание и редактирование тестов внутри приложения.
- Авторизация пользователей и облачная синхронизация.
- Мультимедиа-вопросы (изображения, аудио, видео).
- Автоматическое фоновое обновление каталога тестов.
- Локализация на языки кроме русского и английского.
- CI/CD и процессы деплоя (отдельная фича позже).
